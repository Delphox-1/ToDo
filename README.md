# ToDo

**한국어** | [日本語](docs/README.ja.md) | [English](docs/README.en.md)

할 일, 주간 계획, 캘린더와 프로젝트를 관리하는 개인 플래너입니다. **각자의 서버·DB에 배포하면 원본처럼 로그인하고 PC·폰에서 자동 동기화**할 수 있습니다. 각 배포의 계정과 데이터는 독립적으로 관리됩니다.

개발자의 운영 사이트에는 연결하지 않습니다. 로그인·자동 동기화가 필요하면 아래의 **개인 서버 배포**를 선택하세요. 로그인 없는 PC·Pages 모드도 별도로 제공됩니다.

- 지난 미완료 할 일을 실패·미뤄짐으로 구분
- 휴지통 전체 선택·선택 복원·선택 영구 삭제·휴지통 비우기
- 휴지통 항목은 삭제한 날부터 30일 후 영구 삭제 (앱 로딩·사용·동기화 시 적용)
- 영구 삭제한 항목이 오래된 기기 데이터나 내부 복구본에서 다시 나타나지 않도록 처리
- 휴지통 아래 데이터베이스 검사: PC·Pages는 현재 브라우저, 개인 서버는 로그인한 본인 데이터 검사

**영구 삭제·30일 만료 항목은 앱에서 복원할 수 없습니다.** 내부 복구본도 함께 정리하지만, 직접 내려받은 백업 파일은 수정하지 않습니다. 데이터 검사는 속도 향상을 보장하지 않습니다.

## 주요 기능

- 할 일 추가·수정·완료, 우선순위와 프로젝트 관리
- 주간 일정과 월간 캘린더
- 반복 일정과 할 일 검색
- JSON 파일 백업·복원
- 한국·일본 공휴일 표시

## 표시 언어: 한국어 / 日本語

화면의 **지구본 언어 버튼 → 한국어 또는 日本語**를 선택하면 표시 언어가 바뀝니다. 로그인·회원가입·계정 관리와 플래너 화면에 적용되며, 좁은 휴대폰 화면에서는 지구본 아이콘만 보일 수 있습니다.

선택은 현재 브라우저에 저장되어 새로고침 후에도 유지됩니다. 기기마다 다른 언어를 선택할 수 있으며, **직접 입력한 할 일 제목·프로젝트명·메모는 번역하거나 바꾸지 않습니다.** 언어 전환은 화면을 다시 불러오므로 작성 중인 입력은 먼저 저장하세요.

## 권장: 원본처럼 로그인·자동 동기화하며 사용하기

**각자의 Cloudflare Workers 서버와 D1 DB에 배포하는 모드**를 사용하세요. PC와 폰에서 본인의 같은 주소·계정으로 로그인하면 일정이 자동 동기화됩니다. 본인의 원본 운영 사이트와는 분리됩니다.

**[개인 서버 배포 안내 — 회원가입·로그인·자동 동기화·폰 사용](docs/SELF_HOSTED.ko.md)**

| 사용 방식 | 로그인·서버 저장 | PC·폰 자동 동기화 | 필요한 것 |
| --- | --- | --- | --- |
| **개인 서버 배포 — 권장** | 지원 | 지원 | 본인 Cloudflare 계정·Worker·D1·설정 |
| PC 로컬 실행 | 없음 | 없음 | PC와 Node.js |
| GitHub Pages | 없음 | 없음 | GitHub 계정과 Pages 설정 |

처음 한 번은 각 운영자가 서버·DB·주소·비밀키를 설정해야 합니다. 다운로드나 Fork만으로 서버가 자동 생성되지는 않습니다. ChatGPT 전용 로그인은 독립 배포에 포함하지 않으며, ToDo 자체 회원가입·로그인을 사용합니다. Google 로그인은 본인의 OAuth 키로 선택 설정할 수 있습니다.

### 동기화 모드 로컬 확인

```sh
npm ci
npm run setup:sync
npm run dev:sync
```

[http://127.0.0.1:8787](http://127.0.0.1:8787)을 엽니다. 이 단계는 PC용 로컬 검증이며, 폰에서 접속하려면 위 배포 안내를 완료해야 합니다.

## 방법 1. PC에서 내려받아 실행하기

### 1. 준비

[Node.js](https://nodejs.org/) **22.13.0 이상**을 설치하세요. 설치 후 새 터미널을 열고 다음 명령이 버전을 출력하는지 확인합니다.

```sh
node --version
```

### 2. 코드 다운로드

이 저장소 상단의 **Code → Download ZIP**을 누른 뒤 압축을 풉니다. ZIP 내부에서 바로 실행하지 마세요.

Git을 사용한다면 다음 명령으로 받을 수도 있습니다.

```sh
git clone https://github.com/Delphox-1/ToDo.git
cd ToDo
```

### 3. 실행

**Windows:** 압축을 푼 폴더의 `Start-Local.cmd`를 더블클릭하세요. 열린 명령 창은 앱을 사용하는 동안 유지합니다.

**Windows·macOS·Linux 공통:** `package.json`이 있는 폴더에서 터미널을 열고 실행합니다.

```sh
node scripts/local-server.mjs
```

Node.js와 함께 설치된 npm을 사용하는 경우 `npm run start:local`로 실행해도 됩니다. **`npm install`, `npm ci`, 빌드 작업은 필요하지 않습니다.**

### 4. 브라우저에서 사용

[http://127.0.0.1:4173](http://127.0.0.1:4173)을 열고 할 일을 추가하세요. 로그인이나 회원가입은 없습니다.

터미널을 닫거나 **Ctrl+C**를 누르면 서버가 종료됩니다. 다시 실행한 뒤 **같은 브라우저와 같은 주소**로 접속하면 저장한 기록을 볼 수 있습니다. HTML 파일을 직접 더블클릭하는 대신 위 로컬 주소로 접속하세요.

## 방법 2. 내 웹 주소를 만들고 휴대폰 홈 화면에 추가하기

PC에 별도의 웹 주소나 서버가 없어도 가능합니다. **본인의 GitHub 계정에 저장소를 복사(Fork)하고 GitHub Pages를 켜면**, GitHub가 웹 파일을 호스팅하고 본인용 HTTPS 주소를 제공합니다. 휴대폰에 코드를 내려받거나 Node.js를 설치할 필요는 없습니다.

**다운로드만으로 웹 주소가 생기는 것은 아닙니다.** 아래의 Fork와 Pages 설정을 완료해야 합니다. 여기서 만드는 것은 원본 운영 사이트와 별개인 정적 웹사이트이며, 로그인·DB 서버·자동 기기 동기화는 포함하지 않습니다.

### 1. 본인 계정으로 저장소 복사하기

1. GitHub 계정으로 로그인합니다.
2. 이 저장소 상단의 **Fork**를 누릅니다. 작은 화면에서는 메뉴 안에 있을 수 있습니다.
3. **Owner**에 본인 계정을 선택하고 **Repository name**을 정합니다. 예: `my-todo`.
4. **Create fork**를 누릅니다.
5. 주소가 `github.com/본인아이디/my-todo`처럼 **본인 계정의 저장소**인지 확인합니다. 원본 저장소의 설정을 바꾸는 것이 아닙니다.

GitHub Free에서는 공개 저장소로 Pages를 이용할 수 있습니다. 별도 도메인을 구매할 필요는 없지만, 계정·조직 정책과 GitHub 이용 한도가 적용됩니다.

### 2. GitHub Pages 켜기

1. **복사한 본인 저장소**에서 **Settings → Pages**를 엽니다.
2. **Build and deployment → Source**에서 **Deploy from a branch**를 선택합니다.
3. **Branch**를 `main`, 폴더를 **`/docs`**로 선택합니다. `/(root)`가 아닙니다.
4. **Save**를 누르고 배포가 완료될 때까지 기다립니다.
5. 진행 상태는 **Actions**에서 확인합니다. 완료되면 **Settings → Pages**의 **Visit site** 또는 표시된 사이트 주소를 엽니다.

이 저장소에는 Pages용 `docs/index.html`과 관련 파일이 이미 포함되어 있어, 처음 복사할 때 별도 빌드나 비밀키 설정은 필요하지 않습니다. Pages 설정을 켜기 전에는 사이트가 열리지 않을 수 있습니다.

### 3. 본인의 웹 주소 확인하기

일반적인 프로젝트 주소 형식은 다음과 같습니다. 아래는 설명용 예시이며 실제 사이트 링크가 아닙니다.

```text
https://YOUR-USERNAME.github.io/YOUR-REPOSITORY/
```

예를 들어 계정이 `alice`, 저장소가 `my-todo`이면 `https://alice.github.io/my-todo/` 형태입니다. **실제 주소는 Settings → Pages에 표시된 값을 사용하세요.** PC와 폰에서 같은 주소를 열 수 있고, 내 PC를 계속 켜 둘 필요도 없습니다.

### 4. iPhone에서 홈 화면에 추가하기

1. **Safari**에서 본인의 Pages 주소를 엽니다. GitHub 코드 화면이 아니라 실제 ToDo 화면이 보여야 합니다.
2. **공유** 버튼을 누릅니다. Safari 배치에 따라 페이지 메뉴 안에 있을 수 있습니다.
3. **홈 화면에 추가**를 선택합니다. 보이지 않으면 공유 메뉴의 **동작 편집**에서 찾습니다.
4. **웹 앱으로 열기** 옵션이 표시되면 켭니다.
5. 이름을 정하고 **추가**를 누릅니다.
6. 홈 화면에 생긴 아이콘을 눌러 ToDo를 엽니다.

### 5. Android에서 홈 화면에 추가하기

1. **Chrome**에서 본인의 Pages 주소를 엽니다.
2. 오른쪽 위 **⋮** 메뉴를 누릅니다.
3. **설치 및 바로가기 만들기 → 설치**, **앱 설치**, 또는 **홈 화면에 추가** 중 표시되는 항목을 선택합니다.
4. 안내에 따라 추가한 뒤 홈 화면의 아이콘으로 실행합니다.

메뉴 이름과 앱 창·바로가기 형태는 운영체제와 브라우저에 따라 다릅니다. 앱스토어에서 설치하는 네이티브 앱과는 다르며, **홈 화면에 추가했다고 완전한 오프라인 실행이 보장되는 것은 아닙니다.** 현재 버전은 화면을 새로 불러올 때 인터넷 연결이 필요할 수 있습니다.

### 6. 저장·공유·접속에 관해 알아둘 점

- 호스팅은 각자의 GitHub Pages에서 제공하므로 **개발자의 원본 운영 사이트에는 접속하지 않습니다.**
- 웹사이트를 열면 GitHub에서 파일을 받지만, 일정은 **사용 중인 기기·브라우저에 저장**됩니다. GitHub 저장소에 일정이 업로드되지는 않습니다.
- **같은 Pages 주소를 PC와 폰에서 열어도 일정은 자동 동기화되지 않습니다.** 백업 다운로드·가져오기로 옮기세요.
- Safari에서 쓰던 데이터가 홈 화면 웹 앱에도 그대로 보인다고 가정하지 마세요. 환경이 달라졌다면 기존 화면에서 먼저 백업하고 새 화면에서 가져오세요.
- Pages의 웹 화면은 공개됩니다. 주소를 다른 사람에게 주면 그 사람도 앱을 열 수 있지만, 그 사람의 브라우저에는 별도의 일정이 저장됩니다.
- 저장소 이름이나 웹 주소를 바꿀 때는 먼저 백업하세요. 특히 도메인이 바뀌면 기존 브라우저 저장 공간을 바로 볼 수 없습니다.

### Pages 또는 홈 화면 추가가 안 될 때

| 증상 | 확인할 내용 |
| --- | --- |
| 404 또는 사이트가 아직 없음 | 본인 저장소에서 `main /docs`를 선택했는지, 배포가 완료됐는지 확인하세요. |
| 코드·README만 보임 | `github.com/...` 코드 주소 대신 Pages의 **Visit site** 주소를 여세요. |
| 화면 스타일이나 아이콘이 깨짐 | `/docs` 전체가 복사됐는지 확인하고 Pages에 표시된 주소의 마지막 `/`까지 사용하세요. |
| Settings 또는 Pages가 없음 | 본인 계정의 Fork인지, 저장소 관리 권한과 계정·조직 정책에 제한이 없는지 확인하세요. |
| 홈 화면에 추가 메뉴가 없음 | iPhone은 Safari, Android는 Chrome에서 열고 OS·브라우저를 업데이트하세요. |
| 수정한 코드가 웹에 반영되지 않음 | 개발자가 `npm run build:pages`로 `docs/`를 다시 생성하고 커밋해야 합니다. |

공식 안내: [GitHub Pages 설정](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site), [iPhone 홈 화면에 추가](https://support.apple.com/en-lamr/guide/iphone/iphea86e5236/ios), [Android 웹 앱 설치](https://support.google.com/chrome/answer/9658361?hl=ko&co=GENIE.Platform%3DAndroid).

## PC 로컬·GitHub Pages 모드의 데이터 저장과 백업

- 일정은 서버가 아니라 **현재 브라우저의 localStorage**에 저장됩니다. 개발자에게 전송되지 않습니다.
- 다른 브라우저·프로필·컴퓨터에는 자동으로 동기화되지 않습니다.
- **백업 내려받기**로 JSON 파일을 저장하고, 다른 환경에서는 **백업 가져오기**로 옮길 수 있습니다. 가져오기는 현재 데이터를 바꿀 수 있으므로 먼저 백업하세요.
- 브라우저 사이트 데이터 삭제, 시크릿 모드 종료, 저장 용량 초과로 기록이 사라지거나 저장이 실패할 수 있습니다. 정기적으로 백업하세요.
- 로컬 서버는 이 컴퓨터의 `127.0.0.1`에서만 열립니다. 다른 사람에게 이 로컬 주소를 보내도 그 사람이 내 앱에 접속할 수는 없습니다.
- 공휴일 정보는 인터넷이 연결돼 있으면 공개 공휴일 API에서 보완합니다. 연결이 없어도 할 일 관리는 가능하지만, 포함되지 않은 연도의 공휴일은 표시되지 않을 수 있습니다.

## 실행이 안 될 때

| 증상 | 해결 방법 |
| --- | --- |
| `node` 명령을 찾지 못함 | Node.js 설치 후 터미널을 새로 열거나 컴퓨터를 다시 시작하세요. |
| 파일을 찾을 수 없음 | ZIP 압축을 풀고 `package.json`과 `scripts` 폴더가 있는 위치에서 실행하세요. |
| 포트가 사용 중임 | 이전 ToDo 실행 창을 닫고 다시 실행하세요. 필요하면 아래 명령으로 다른 포트를 선택합니다. |
| 이전 기록이 보이지 않음 | 이전에 쓰던 브라우저·프로필·주소·포트로 접속하세요. |
| 화면이 갱신되지 않음 | 서버가 실행 중인지 확인하고 브라우저를 새로고침하세요. |

```sh
node scripts/local-server.mjs --port 4174
```

다른 포트를 선택하면 [http://127.0.0.1:4174](http://127.0.0.1:4174)로 접속합니다. 포트가 다르면 브라우저 저장 공간도 다르므로, 기존 기록은 원래 포트로 접속하거나 백업 파일을 가져와야 볼 수 있습니다.

# ToDo

[한국어](../README.md) | **日本語** | [English](README.en.md)

タスク、週間スケジュール、カレンダー、プロジェクトを管理する個人向けプランナーです。**自分のサーバーとDBにデプロイすると、ログインしてPCとスマートフォン間で自動同期**できます。各サイトのアカウントとデータは独立しています。

開発者の運用サイトには接続しません。ログインや自動同期が必要なら **個人サーバーへのデプロイ** を選んでください。ログイン不要のPC・Pagesモードも別途利用できます。

- 期限を過ぎた未完了タスクを「失敗」「延期」に分類
- ゴミ箱の全選択・選択した項目の復元・完全削除・ゴミ箱を空にする機能
- 削除から30日経過した項目を完全削除（起動・使用・同期時に処理）
- 古い端末のデータや内部の復元用データから削除済み項目が復活するのを防止
- ゴミ箱の下にデータベース検査を追加。PC・Pagesでは現在のブラウザー、個人サーバーではログイン中の本人のデータを検査

**完全削除・30日経過後の項目はアプリから復元できません。** 内部の復元用データも整理しますが、ダウンロード済みのバックアップファイルは変更しません。検査による速度向上は保証されません。

## 主な機能

- タスクの追加・編集・完了、優先度とプロジェクトの管理
- 週間スケジュールと月間カレンダー
- 繰り返しの予定とタスク検索
- JSONファイルによるバックアップと復元
- 韓国・日本の祝日表示

## 表示言語：한국어 / 日本語

画面の**地球アイコンの言語ボタン → 한국어 または 日本語**で表示言語を切り替えます。ログイン、新規登録、アカウント管理、プランナーに適用されます。スマートフォンの狭い画面では地球アイコンだけが表示される場合があります。

選択はブラウザーに保存され、再読み込み後も維持されます。端末ごとに異なる言語を選べます。**入力したタスク名、プロジェクト名、メモは翻訳・変更されません。** 切り替え時には画面が再読み込みされるため、編集中の内容は先に保存してください。

## 推奨：自分のサーバーでログインと自動同期を使う

自分のCloudflareアカウントに **WorkersとD1** をデプロイすると、パソコンとスマートフォンで同じURL・アカウントを使って予定を同期できます。開発者の運用サイトとは別の構成です。

**[個人サーバーへのデプロイ手順 — 登録・ログイン・同期・スマートフォン](SELF_HOSTED.ja.md)**

| 利用方法 | ログイン・サーバー保存 | PC・スマートフォン間の自動同期 | 必要なもの |
| --- | --- | --- | --- |
| **個人サーバー — 推奨** | 対応 | 対応 | 自分のCloudflareアカウント、Worker、D1、設定 |
| PCローカル | なし | なし | パソコンとNode.js |
| GitHub Pages | なし | なし | GitHubアカウントとPages設定 |

初回にサーバー、DB、URL、シークレットを設定する必要があります。ダウンロードやForkだけではサーバーは作成されません。ChatGPT専用ログインは独立版に含まれず、ToDo独自のアカウントを使います。Google認証は自分のOAuthキーで追加できます。

### 同期モードをローカルで確認

```sh
npm ci
npm run setup:sync
npm run dev:sync
```

[http://127.0.0.1:8787](http://127.0.0.1:8787) を開きます。これはPC上の確認用です。スマートフォンから使うには、上記の公開手順を完了してください。

## 方法1：パソコンにダウンロードして実行する

### 1. 準備

[Node.js](https://nodejs.org/) **22.13.0以上**をインストールします。新しいターミナルを開き、次のコマンドでバージョンが表示されることを確認してください。

```sh
node --version
```

### 2. コードをダウンロード

リポジトリ上部の **Code → Download ZIP** を選び、ZIPファイルを展開します。ZIPの中から直接実行しないでください。

Gitを使う場合は、次のコマンドでも取得できます。

```sh
git clone https://github.com/Delphox-1/ToDo.git
cd ToDo
```

### 3. 起動

**Windows:** 展開したフォルダー内の `Start-Local.cmd` をダブルクリックします。アプリの使用中は、開いたコマンドウィンドウを閉じないでください。

**Windows・macOS・Linux共通:** `package.json` があるフォルダーでターミナルを開き、次のコマンドを実行します。

```sh
node scripts/local-server.mjs
```

Node.jsに付属するnpmを使う場合は、`npm run start:local` でも起動できます。**`npm install`、`npm ci`、ビルドは不要です。**

### 4. ブラウザーで使う

[http://127.0.0.1:4173](http://127.0.0.1:4173) を開き、タスクを追加してください。ログインやユーザー登録はありません。

ターミナルを閉じるか **Ctrl+C** を押すとサーバーが停止します。再起動後に**同じブラウザーと同じURL**で開くと、保存した予定を確認できます。HTMLファイルを直接開くのではなく、上記のローカルURLにアクセスしてください。

## 方法2：自分のWebサイトを作り、スマートフォンのホーム画面に追加する

パソコン用の公開URLやサーバーを持っていなくても利用できます。**自分のGitHubアカウントにリポジトリをForkし、GitHub Pagesを有効にする**と、GitHubがファイルを配信し、自分用のHTTPS URLを提供します。スマートフォンにコードやNode.jsをインストールする必要はありません。

**ダウンロードだけではWebサイトは公開されません。** 以下のForkとPagesの設定が必要です。作成されるのは開発者の運用サイトとは別の静的サイトです。ログイン、DBサーバー、端末間の自動同期は含まれません。

### 1. 自分のアカウントにForkする

1. GitHubにログインします。
2. このリポジトリの **Fork** を選びます。小さい画面ではメニュー内にある場合があります。
3. **Owner** に自分のアカウントを選び、**Repository name** を指定します。例：`my-todo`。
4. **Create fork** を選びます。
5. URLが `github.com/自分のユーザー名/my-todo` のように、**自分のリポジトリ**になっていることを確認します。元のリポジトリの設定を変更するわけではありません。

GitHub Freeでは公開リポジトリでPagesを利用できます。独自ドメインの購入は不要ですが、アカウントや組織のポリシー、GitHubの利用制限が適用されます。

### 2. GitHub Pagesを有効にする

1. **Forkした自分のリポジトリ**で **Settings → Pages** を開きます。
2. **Build and deployment → Source** で **Deploy from a branch** を選びます。
3. **Branch** を `main`、フォルダーを **`/docs`** にします。`/(root)` ではありません。
4. **Save** を選び、デプロイが完了するまで待ちます。
5. **Actions** で進行状況を確認できます。完了したら、**Settings → Pages** の **Visit site** または表示されたURLを開きます。

Pages用の `docs/index.html` と関連ファイルは同梱されています。最初の公開時にビルドや秘密鍵の設定は不要です。Pagesを有効にする前は、サイトが表示されない場合があります。

### 3. 自分のURLを確認する

一般的なプロジェクトサイトのURLは次の形式です。これは説明用で、実際のサイトへのリンクではありません。

```text
https://YOUR-USERNAME.github.io/YOUR-REPOSITORY/
```

例えばユーザー名が `alice`、リポジトリ名が `my-todo` なら、`https://alice.github.io/my-todo/` という形式です。**実際のURLはSettings → Pagesに表示されたものを使ってください。** パソコンとスマートフォンの両方から開けます。自分のパソコンを起動したままにする必要はありません。

### 4. iPhoneのホーム画面に追加する

1. **Safari** で自分のPages URLを開きます。GitHubのコード画面ではなく、ToDoの画面を表示してください。
2. **共有**を選びます。Safariのレイアウトによってはページメニュー内にあります。
3. **ホーム画面に追加**を選びます。見つからない場合は、共有メニューの**アクションを編集**で探してください。
4. **Webアプリとして開く**が表示されたらオンにします。
5. 名前を指定して**追加**を選びます。
6. ホーム画面に追加されたアイコンからToDoを開きます。

### 5. Androidのホーム画面に追加する

1. **Chrome** で自分のPages URLを開きます。
2. 右上の **⋮** メニューを開きます。
3. **インストールとショートカットの作成 → インストール**、**アプリをインストール**、**ホーム画面に追加**など、表示された項目を選びます。
4. 案内に従って追加し、ホーム画面のアイコンから起動します。

メニュー名やアプリ・ショートカットの表示方法は、OSやブラウザーによって異なります。ストアから入れるネイティブアプリとは異なり、**ホーム画面への追加だけで完全なオフライン動作が保証されるわけではありません。** 現在のバージョンでは、画面の読み込みにインターネット接続が必要な場合があります。

### 6. 保存・共有・アクセスについて

- 各自のGitHub Pagesがファイルを配信するため、**開発者の運用サイトには接続しません。**
- サイトのファイルはGitHubから取得しますが、予定は**使用中の端末・ブラウザー内**に保存されます。予定がGitHubリポジトリにアップロードされることはありません。
- **同じPages URLをパソコンとスマートフォンで開いても、自動同期はされません。** バックアップのダウンロードとインポートで移してください。
- Safariで保存した予定がホーム画面のWebアプリにもそのまま表示されるとは限りません。環境が変わる場合は、先に元の画面でバックアップしてから、新しい画面でインポートしてください。
- Pagesの画面は公開されます。URLを他の人に渡せばその人もアプリを開けますが、予定はそれぞれのブラウザーに別々に保存されます。
- リポジトリ名やURLを変える前にバックアップしてください。特にドメインが変わると、以前の保存領域には直接アクセスできません。

### Pagesやホーム画面への追加がうまくいかないとき

| 症状 | 確認すること |
| --- | --- |
| 404になる、サイトがない | 自分のリポジトリで `main /docs` が選ばれ、デプロイが完了しているか確認してください。 |
| コードやREADMEしか表示されない | `github.com/...` ではなく、Pagesの **Visit site** から開いてください。 |
| 表示やアイコンが崩れる | `/docs` 全体がコピーされているか確認し、PagesのURLを末尾の `/` まで使ってください。 |
| SettingsやPagesが見つからない | 自分のForkか、管理権限やアカウント・組織の制限がないか確認してください。 |
| ホーム画面に追加できない | iPhoneはSafari、AndroidはChromeを使い、OSとブラウザーを更新してください。 |
| コードの変更がサイトに反映されない | 開発者は `npm run build:pages` で `docs/` を再生成し、コミットする必要があります。 |

公式ガイド：[GitHub Pagesの設定](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site)、[iPhoneのホーム画面に追加](https://support.apple.com/en-lamr/guide/iphone/iphea86e5236/ios)、[AndroidでWebアプリをインストール](https://support.google.com/chrome/answer/9658361?hl=ja&co=GENIE.Platform%3DAndroid)。

## PCローカル・GitHub Pagesモードのデータ保存とバックアップ

- 予定はサーバーではなく、**使用中のブラウザーのlocalStorage**に保存されます。開発者には送信されません。
- 別のブラウザー、プロファイル、パソコンには自動で同期されません。
- バックアップのダウンロード機能でJSONファイルを保存し、別の環境でインポートするとデータを移せます。インポートによって現在のデータが変わる場合があるため、先にバックアップしてください。
- サイトデータの削除、プライベートブラウズの終了、保存容量の不足により、データが消えたり保存に失敗したりする場合があります。定期的にバックアップしてください。
- ローカルサーバーは、このパソコンの `127.0.0.1` でのみ待ち受けます。このローカルURLを他の人に送っても、その人があなたのアプリに接続できるわけではありません。
- インターネット接続がある場合、公開APIから祝日情報を補完します。オフラインでもタスク管理は使えますが、同梱データにない年の祝日は表示されない場合があります。

## 起動できないとき

| 症状 | 対処方法 |
| --- | --- |
| `node` が見つからない | Node.jsをインストールし、ターミナルを開き直すかパソコンを再起動してください。 |
| ファイルが見つからない | ZIPを展開し、`package.json` と `scripts` があるフォルダーで実行してください。 |
| ポートが使用中 | 以前起動したToDoのウィンドウを閉じて再実行してください。必要なら下記のコマンドでポートを変更できます。 |
| 以前の予定が表示されない | 以前と同じブラウザー、プロファイル、URL、ポートを使用してください。 |
| 画面が更新されない | サーバーが起動していることを確認し、ページを再読み込みしてください。 |

```sh
node scripts/local-server.mjs --port 4174
```

この場合は [http://127.0.0.1:4174](http://127.0.0.1:4174) を開きます。ポートが変わるとブラウザーの保存領域も変わります。以前のデータを見るには元のポートを使うか、バックアップをインポートしてください。

## 開発と検証

追加パッケージを使わず、Node.jsの標準機能で動作します。テストは次のコマンドで実行できます。

```sh
npm test
```

ブラウザー側のコードは `public/planner/`、ローカルサーバーは `scripts/local-server.mjs` にあります。個人の予定データはリポジトリに含まれていません。

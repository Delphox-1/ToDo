# Deploy your own server — sign-in and automatic sync

[한국어](SELF_HOSTED.ko.md) | [日本語](SELF_HOSTED.ja.md) | **English** · [README](README.en.md)

Deploy **Cloudflare Workers (app server) and D1 (database)** in your own account. Open the same deployed URL on your PC and phone and sign in with the same ToDo account to sync plans, projects, and notes. This mode does not use the developer's live server or database.

## Features and differences

- ToDo sign-up and sign-in, per-account storage, sign-out, and account deletion
- Tasks, recurring events, weekly plans, calendar, projects, search, backup, and restore
- Multiple-device sync and conflict handling for concurrent edits
- Phone home-screen access
- Google sign-in and account linking after configuring your own OAuth client

The original site's **ChatGPT-specific sign-in** belongs to its hosting platform and is not included in this independent deployment. Use a ToDo account instead. Original accounts and plans do not migrate automatically; transfer plans using a backup if needed.

**GitHub Pages and PC-local mode are separate options.** Enabling Pages alone does not provide server authentication or sync.

## 1. Prerequisites

You need your own GitHub account and fork, a Cloudflare account, Git, and Node.js **22.13.0 or later**. Check Cloudflare's usage limits and pricing. Each operator creates accounts, signs in, creates the database, and deploys using their own credentials. This guide does not promise free or unlimited operation.

## 2. Download and create local configuration

Replace `YOUR-USERNAME` with your GitHub username. Adjust the repository URL and directory if you renamed your fork.

```sh
git clone https://github.com/YOUR-USERNAME/ToDo.git
cd ToDo
npm ci
npm run setup:sync
```

`setup:sync` creates these **local-only** files and preserves existing ones:

- `self-hosted/wrangler.json`: your Worker, database, and URL settings
- `self-hosted/.dev.vars`: an automatically generated local authentication secret

Both are excluded from Git. Do not use the developer's live site, keys, or database.

## 3. Test locally first

```sh
npm run dev:sync
```

This automatically applies local database migrations. Open [http://127.0.0.1:8787](http://127.0.0.1:8787), choose **회원가입 (Sign up)**, and create a ToDo account. Sign in with the same account in another browser to check your saved plans.

This local URL works only on the current PC. Phone access requires the public deployment below. Local and production databases are also separate. Press **Ctrl+C** to stop.

## 4. Create a database in your Cloudflare account

Stop the local server, then run:

```sh
npx wrangler login
npx wrangler d1 create todo-db --config self-hosted/wrangler.json
```

Sign in to your own Cloudflare account. Note the `database_id` returned by the database creation command. If the database already exists, use its ID rather than creating it again.

## 5. Edit your production configuration

Update the relevant fields in `self-hosted/wrangler.json`. The following is a **partial example**, not a replacement for the full file. Keep other settings, including `main`, `assets`, and compatibility options.

```json
{
  "name": "my-todo",
  "vars": {
    "TODO_AUTH_ORIGIN": "https://my-todo.YOUR-SUBDOMAIN.workers.dev"
  },
  "d1_databases": [
    {
      "binding": "DB",
      "database_name": "todo-db",
      "database_id": "YOUR-D1-DATABASE-ID",
      "migrations_dir": "./migrations"
    }
  ]
}
```

Use your Worker name for `name`, your public **HTTPS origin without a path or trailing slash** for `TODO_AUTH_ORIGIN`, the database ID from step 4, and the matching database name. Keep `binding: "DB"` and `migrations_dir` unchanged.

Check or configure your account's `workers.dev` subdomain in Cloudflare. Do not leave `YOUR-SUBDOMAIN` unchanged. If you use a custom domain, configure its connection to the Worker first.

## 6. Register a production authentication secret

Copy the value generated by the first command and paste it when the second command prompts:

```sh
node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"
npx wrangler secret put TODO_AUTH_SECRET --config self-hosted/wrangler.json
```

If Wrangler offers to create a missing Worker, confirm that its name matches your own configuration. Keep the value out of public GitHub files and store it safely. Changing it after launch affects existing sessions.

The local `.dev.vars` file is not automatically uploaded. **You must register the production secret separately.**

## 7. Apply database migrations and deploy

```sh
npm run db:sync:remote
npm run deploy:sync
```

The first command applies outstanding migrations to your **remote database** in order. The second deploys the app and its static assets. No separate frontend build is needed.

The scripts reject production deployment with the example database ID or a local URL. Check step 5 if validation fails. Cloudflare authentication, permissions, and quota errors must be resolved in your own account.

## 8. Verify deployment and sync your PC and phone

1. Open the deployed HTTPS URL and confirm that the sign-in screen loads.
2. Optionally check that `https://YOUR-APP-DOMAIN/api/health` returns `{"ready":true}`. A 503 response means you should check migrations, database binding, secret, and origin configuration.
3. **Register an account on the deployed site.** Local test accounts are not in the production database.
4. Use the **same HTTPS URL and ToDo account** on both devices.
5. Edit a task or note on one device and check that the other receives the change.

Changes are sent to the server, and visible pages check for other devices' updates **about every 10 seconds**. Sync also runs when the page regains focus or connectivity returns. This is not instant push-based sync; network conditions can cause delays. Previously stored records remain editable offline, but confirm sync has completed before moving to another device. Opening a fresh page entirely offline is not guaranteed.

On your phone, open your own deployed URL in Safari or Chrome and use **Share/menu → Add to Home Screen/Install app**. Your PC does not need to remain on. See the [README](README.en.md) for the phone menu steps.

## 9. Optional Google sign-in

Standard username/password sign-in works without Google configuration. To enable Google, create a **Web application OAuth client** in your own Google Cloud project and register this redirect URI:

```text
https://YOUR-APP-DOMAIN/api/auth/callback/google
```

For local testing, also register `http://127.0.0.1:8787/api/auth/callback/google` and add your development keys to the local `.dev.vars` file.

Register production keys with:

```sh
npx wrangler secret put GOOGLE_CLIENT_ID --config self-hosted/wrangler.json
npx wrangler secret put GOOGLE_CLIENT_SECRET --config self-hosted/wrangler.json
```

Configure your Google consent screen, test users, and publishing status as appropriate. Without keys, the Google button is disabled. To use Google with an existing username account's plans, choose **sign in with your username → account management → link Google account**.

## Operations and backups

Data belongs to the deployment operator's D1 database. Deleting the server or database can remove user data. Maintain regular JSON and database backups, including before remote migrations.

The current configuration allows visitors to register accounts. Restricting membership requires an additional sign-up or access policy. Separate operators' deployments do not share accounts or plans. Each operator manages their database, URL, authentication secret, and Google settings; keep credentials out of the repository.

## Verification

```sh
npm test
npm run check:sync
```

With the local sync server running, you can also run the following integration check. It deletes its own generated test accounts afterward and refuses production URLs.

```sh
node scripts/verify-selfhost.mjs
```

Local Worker/D1 integration and production bundle generation have been verified. Each operator must still verify their actual Cloudflare deployment and Google OAuth connection in their own account.
